# 工作流各阶段操作细节

## S0 可行性评估

收到 SRT 后第一条回复只做评估，不写代码、不下载素材：

1. **稿件基本事实**：句数、总长（末帧时码）、平均句长、主题。全部可从文件核验。
2. **可行性分级**：可直接实现 / 需外部素材 / 不可实现。2D 几何 + 数字 + 文字驱动的稿件都可直接实现。
3. **候选技术路径**（A 从零重做 / B 迁移复用旧图元 / C 不重做），给工作量对比。
4. **风险表**：依赖安装、渲染耗时（5810 帧 1080p ≈ 6 分钟量级）、数据准确性、重复劳动（硬盘上是否已有同稿成片）。
5. **稿件层面已知问题**：台词与画面的口径矛盾（如 48.61% 只对应骰宝不对应轮盘），处理原则是**不改台词、画面规避**。
6. 用选择题让用户定：制作路径 / 画幅分辨率 / 视觉方向 / 音频字幕方式。

## S2 节拍表（beat-sheet）

- 一句一幕太碎。短促稿件按**语义合并**，81 句 → 30–36 幕是常见密度。
- 帧界从 SRT 时码直推：`start_frame = round(start_ms / 1000 * fps)`，写入 `src/acts/acts.ts` 作为**单一事实来源**，所有 Composition 从它取帧界。
- 标出节奏对比点（静 vs 动、单数字 vs 数据密集）。
- 列出**全部待复算数字**（台词中出现的每个百分比/概率/年份）。

### 数字复算（G1 后立即做，全片可信度地基）

- 概率算式用 Python 直接算；「输光率」类用固定种子蒙特卡洛（20 万局级），种子写死保证可复现。
- 抓口径不符：如「99.49% 输光率」对应「每注 1 元押到翻倍或归零（期望约 940 注）」，与台词「拆成一百次」不符 → 不改台词，画面加口径标注。
- 文献引用逐项核验（期刊/年/卷期页/实验细节），二手数据措辞降级为「多项研究：约 X%」。

## S2 视觉方向（styleframe）

- 3 张关键静帧：钩子幕 / 数据幕 / 机制幕。必须**真实渲染**（`npx remotion still`），不用截图模拟。
- 一次定死色板 token（9 色左右，强调色全片限量落点）+ 运动 token + 文字入场语法（3–4 种）。
- 用户可单独调：底色深浅、强调色用量、字体气质。

## S4 分镜（storyboard）

每幕一行：帧界 / 主视觉 / 主运动 / 转场理由 / **静音验收锚点**（无音轨时图形必须自己把话说清）。
转场预算全片统筹：硬切 / 同图元续画 / 缩放位移 / 回卷 / 叠化，比例大致 14:8:7:1:1。

## S5 垂直切片

- 不必拘泥 5–10 秒：选**数据密度峰值**的 3–4 幕（如轮盘几何 + 结论数字 + 动态插入 + 新机械）一次验完四类最高风险场景。
- 切片渲染完立即做五级验证（见 qa-gates.md），抓出的 bug 修完重渲再交 G4。

## S6 铺幕

- **续画幕**共享几何常量：A 幕末态与 A+1 幕初态用同一组导出常量（如 `SPLIT = {win: 560, crack: 850, payback: 990}`），保证不跳变。
- 相机拉远类幕：把上一幕末态原样 scale，不重画。
- spring 是预算资源：全片 2–3 次，用在情绪重拍上，其余用 interpolate + easing。

## S7 整片渲染与交付

1. 全片渲染（带验算门）→ 2. blackframe=0 检查 → 3. 接触印相（40 格）目检叙事完整 → 4. ffprobe 复核规格 → 5. 抽 4–6 个新幕关键帧全分辨率目检。
交付物：成片 mp4 + 外挂 SRT（不烧字幕时）+ 接触印相 + 状态文件全套。
